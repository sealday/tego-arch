# 模型同步策略

代码已经移除接口，架构图却仍保留旧关系；ADR 仍是 accepted，部署记录和线上观测又指向不同版本。把这些文件双向复制只会让最后一次写入覆盖真实差异。同步不是双向复制；每项事实先指定一个当前权威。

本文提供一个可迁移判断：先按事实粒度声明权威，再选择生成、验证或观测关系，把差异送入同一处置闭环。生成关系重建派生产物，验证关系只报告合同差异，观测关系保留实际状态。

证据范围只覆盖本站内容仓库的可重建产物、受测接口、架构图源、ADR 状态、部署记录与运行查询，以及一个费用申报说明性场景。它不把教学场景写成生产事实，也不把一次测试、部署或观测扩张为长期健康结论；[建模目录](/modeling)提供其他模型入口。

## 学习问题

- 如何把“代码或 Git 是真相”改写为每项事实只有一个当前权威的可执行合同？
- 何时应该生成派生产物，何时只能验证两个事实，何时必须保留实际观测？
- 如何区分内容漂移、结构漂移、决策漂移和运行漂移，并保留检测失败产生的未知？
- 如何在不手改派生产物、不改写历史 ADR 的前提下修复差异？
- 如何用精确发布身份和独立复放关闭一次同步循环，而不夸大证据？

## 同步目标与输入

同步的目标不是让所有载体文字相同，而是让每项事实的写入权、派生方向、检测证据和修复方向明确。输入包括主题状态、MDX 元数据、代码接口、已批准模型与图源、ADR、版本化部署声明、实际部署记录和运行观测；两个来源争夺同一事实时，先拆细事实或人工裁决，不能自动互相覆盖。

生成是从当前权威确定性重建派生产物；验证是按合同比较两个独立事实并只报告差异；观测是读取并保留实际状态，不把它反写成期望状态。检测器不可用时状态是“未知”，不是“无漂移”或 PASS。

## 漂移检测闭环

四类漂移按内容漂移 → 结构漂移 → 决策漂移 → 运行漂移排列。内容漂移比较 backlog、front matter 与生成清单；结构漂移比较受测接口与模型关系；决策漂移比较有效 ADR 与实现；运行漂移比较期望提交、实际部署身份和线上观测。

状态词汇限定为：`待分级`、`阻断`、`修复中`、`接受差异`、`已验证关闭`、`未知`。接受差异还必须记录理由、责任类型、复查条件和到期点；已验证关闭必须指向修复后的检测与发布证据。

闭环按以下顺序执行：

1. **声明权威：** 把事实拆到足以拥有单一写者的粒度，并记录关系、责任类型和非证明边界。
2. **生成或验证：** 能确定性派生的产物自动生成；独立事实按合同比较或观测。
3. **检测差异：** 保存输入、比较结果、时间和版本身份；检测失败保留为未知。
4. **分级处置：** 决定自动重建、人工裁决、接受差异或阻断发布，并分配责任类型。
5. **重建证据：** 修改权威来源或新增替代 ADR，重新生成并重跑所有受影响检测。
6. **发布复核：** 用精确提交、workflow run、jobs、状态和线上 route 复核，不扩张结论。

## 完成判断

闭环完成要求每项事实都有当前权威、关系类型、责任类型和修复方向；四类漂移已检测或明确说明不适用；所有阻断项关闭，所有未知仍可见；接受差异拥有理由、复查条件和到期点；ADR 冲突通过恢复实现或新增替代记录解决；发布证据绑定精确提交、run、jobs、状态与线上 route。

ADR 记录决定与状态，但不证明实现遵循决定。部署成功只证明指定提交完成指定发布流程，不证明全部运行健康。最终还需要一位未参与修复的人从台账与图中独立复述权威、方向、差异、修复和非证明边界。

## 常见失败

最常见的失败是宣布“代码永远权威”或“Git 永远权威”，从而让实际部署、运行观测或有效决定失去自己的写入边界。另一类失败是检测器无输出便记为同步，或直接修改 generated JSON、SVG 与索引，掩盖权威输入或生成器中的问题。

删除旧 ADR 会伪造决策连续性；正确做法是恢复仍有效决定要求的实现，或新增决定并建立 superseded 关系。期望部署与实际状态不一致时，应保留真实观测，经过裁决后前滚、回滚或修改期望，再产生新的部署身份和复核证据。

## 完整演练

**说明性场景：** 费用申报系统边界内包含 Web 应用、申报 API、申报数据库和支付任务执行器，员工与银行支付服务位于边界外。受控差异只有一个：代码已移除申报 API 与支付任务执行器之间的接口，架构图仍保留旧关系；不补写协议、事故、指标或生产效果。

1. 盘点主题状态、内容元数据、代码接口、图中语义、ADR、期望部署、实际部署与运行观测。
2. 把每项事实拆到单一写者粒度，指定当前权威、责任类型与非证明边界。
3. 把每条同步关系分类为生成、验证或观测。
4. 注入一个受控差异：代码移除接口，但架构图仍保留旧关系。
5. 把差异分类为结构漂移，记录严重度与当前状态，并分配责任类型。
6. 裁决结构事实权威，修改代码或图源，再重建受影响的派生产物与检测证据。
7. 由未参与修复的人独立复放检测，并用精确提交、发布流程与线上 route 完成发布复核。

演练只证明学习者能够执行合同。接口测试证明受测结构差异，图对验证证明派生语义一致；两者都不证明部署或运行状态。修复必须回到经裁决的权威，然后重建检测与发布证据。
