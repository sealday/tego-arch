# 自主系统平台与模型网关

## 为什么学

模型网关处理的不只是统一应用程序编程接口（Application Programming Interface，API），智能体（Agent）平台处理的也不只是框架托管。模型与能力路由、租户身份、预算、护栏（guardrail）、长时状态、协议、评估和隔离分布在不同控制点；如果不先划清责任，单个“平台层”会掩盖失败与越权路径。

## 前置能力与跳过条件

读者应先理解自主式控制权、生产隔离和恢复责任。如果已经能为一次智能体调用链说明路由依据、调用者身份、虚拟密钥、配额与成本归属、护栏时序、状态所有者、智能体间协议（Agent2Agent Protocol，A2A）与模型上下文协议（Model Context Protocol，MCP）边界、评估信号和执行隔离，可以跳过必读起点。

## 核心问题

- 模型、供应商和工具能力由谁路由，回退如何避免改变语义或合规边界？
- 用户、服务、智能体、虚拟密钥和上游凭据如何关联，配额与成本记到谁名下？
- 输入、输出、工具调用和人工审批的护栏应分别放在哪个强制点？
- 编排状态、业务事实、长期记忆、智能体间协议任务与模型上下文协议工具会话如何分界？
- 质量、延迟、成本、安全事件和租户故障半径如何被观察和隔离？

## 推荐学习顺序

1. 先定义模型与能力目录、路由约束、回退条件和不可跨越的合规边界。
2. 再串起调用者身份、虚拟密钥、上游凭据、配额、预算和成本归属。
3. 然后标出输入、输出、工具执行前后与人工审批位置，明确每道护栏能阻止什么。
4. 接着划分编排状态、业务事实与长期记忆，再判断智能体间协议或模型上下文协议是否对应真实的跨智能体或工具接入边界。
5. 最后建立评估、追踪、成本和安全信号，并用租户、任务和执行环境隔离故障。

## 必读起点

[兼容性、互操作与版本迁移](/quality-attributes/qa-07)用于分开验证来源、线上格式与语义兼容性，并把协议互操作与业务兼容放进版本迁移边界。

[安全、隐私（Privacy）与信任边界](/quality-attributes/qa-05)用于盘点主体、数据目的和每次授权上下文变化；[可运维性、可观测性与事件闭环](/quality-attributes/qa-08)用于把智能体调用链的信号、诊断、受控动作和用户可见恢复连起来。

[LiteLLM Virtual Keys](https://docs.litellm.ai/docs/proxy/virtual_keys) 用于理解虚拟密钥、预算与网关治理入口；[OpenAI Agents SDK 多智能体文档](https://openai.github.io/openai-agents-python/multi_agent/) 用于理解多智能体管理者（Manager）与移交（Handoff）等控制原语；[A2A 文档](https://a2a-protocol.org/latest/) 与 [MCP 入门](https://modelcontextprotocol.io/docs/getting-started/intro) 用于区分跨智能体任务互操作和工具或数据接入。它们描述各自机制，不共同构成一套开箱即用的平台架构。

## 查漏补缺

[Envoy AI Gateway 入门](https://aigateway.envoyproxy.io/docs/getting-started/) 可用于比较基于网关基础设施的模型流量入口，[Awesome Agentic Engineering Resources](https://github.com/EthicalML/awesome-agentic-engineering-resources) 可用于发现评估、安全、编排和平台材料。后者是社区索引；二者都不替代对目标版本、供应商契约和本地风险的核验。

## 深入拓展

只有在真实平台需求出现后，才沿官方文档和上游仓库核对路由 API、身份传播、状态存储、协议版本、追踪字段和失败恢复。不要从案例或索引推导供应商等价性，也不要把协议互通写成权限、事务或结果质量保证。

## 延伸问题

- 跨供应商模型能力、语义回退与数据驻留约束如何被验证？
- 端用户、服务、智能体、工具与上游模型之间如何委托和撤销身份？
- 输入、输出、工具执行与人工审批的多层护栏如何接受绕过测试和审计？
- 智能体间协议与模型上下文协议如何协商版本、发现能力、授权调用并从失败中恢复？
- 离线评估、在线反馈、追踪、成本与安全事件如何关联到同一任务？
- 多租户执行沙箱、缓存和记忆如何防止泄漏并限制故障半径？

## 实践产出

为一次端到端智能体请求保留一张平台控制表：记录路由依据、身份和凭据、配额与成本、每道护栏、状态所有者、协议边界、评估与追踪信号，以及租户和执行环境隔离。

## 检查点

追踪一次带工具副作用的智能体请求，说明网关和编排器各自决定什么、身份和预算如何传播、护栏在何处强制、状态在哪里恢复、智能体间协议与模型上下文协议是否必要，以及哪项本地证据仍不足以支持生产结论。
