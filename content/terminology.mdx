# 术语规范

本页规定贡献者在正文、表格和图示中如何书写术语。它负责统一表达，不替代概念文章，也不作为技术事实的来源；概念边界仍由对应主题页说明，事实判断仍须回到资料库登记的证据。

## 中文优先

面向读者的说明以中文为主。已有稳定中文译名时，先写规范中文，再按注册表给出的形式补充英文和缩写。完整形式为 `中文（English，ACRONYM）`；没有缩写时省略缩写，没有适合翻译的名称时保留官方写法并补充必要的中文上下文。

中文优先不是逐字翻译。译名必须保持原概念的责任边界，不能为了行文顺畅合并不同概念，也不能把局部实现习惯写成通用定义。

## 首次出现与后续使用

一篇页面第一次引入受管术语时，使用下表“首次出现”列的完整形式。后续出现只使用“后续使用”列列出的写法；不要自行改变大小写、标点、词序或缩写。

同一页面的标题、摘要与正文共同计算首次出现。若读者可能从独立图表、折叠内容或深层链接直接开始阅读，可在该局部重新给出完整形式，但不因此创造新的别名。

## 专名与缩写

产品、项目、组织、协议和标准等专名保持官方拼写。需要中文说明时，在专名前后补充其角色，不翻译品牌名、仓库名或协议标识。注册表将专名列为规范项时，以其中的首次与后续写法为准。

缩写只有在能够减少重复且不会造成歧义时才使用。首次出现先给出中文、英文全称和缩写，后续才可单独使用注册表允许的缩写。不要为单篇文章临时创造缩写，也不要用大小写近似的写法代替规范形式。

## 代码、命令、路径、标识符与字段名

代码、命令、路径、标识符与字段名保持可复制的原始字符，并用行内代码或代码块表示，例如 `npm run build`、`content/terminology.mdx` 和 `canonical_zh`。不要翻译、全角化或改变大小写；需要解释时，在代码形式之外补充中文说明。

界面标签或 API 字段若必须逐字对应实现，也按原值保留。普通叙述中的概念名称仍遵循中文优先规则，不能因为实现中使用英文标识符就把正文改成英文术语堆叠。

## 文献原题

论文、标准、书籍、报告和文章的文献原题保持出版时的语言与拼写。正文可先用中文说明其主题，再以书名号、引号或链接呈现原题；不要把自译标题冒充正式标题，也不要用标题本身替代来源登记和事实论证。

## 图中文字

图中文字同样遵循中文优先、首次出现和后续使用规则。节点与连线标签优先使用简洁的规范中文；专名、缩写以及必须与实现对应的代码标识保持原样。图的替代文本和正文说明应与图中术语一致，使只读取文本的读者获得同一表达。

空间不足不是创造简称的理由。若完整形式会损害可读性，应在图前正文完成首次引入，并在图中使用注册表允许的后续写法。

## 贡献流程

新增术语或调整写法时，只修改 `data/terminology.json` 中的规范记录，并同步修改实际使用该术语的页面。每条记录应说明规范中文、首次出现、后续使用、允许或禁止的别名、使用边界与稳定顺序。

提交前运行术语注册表、术语页面和侧栏导航测试，再运行类型检查与站点构建。评审时检查译名是否忠于原概念、专名与标识符是否保持原样、图文是否一致，以及改动是否误把本页扩写成概念定义或事实来源页。
