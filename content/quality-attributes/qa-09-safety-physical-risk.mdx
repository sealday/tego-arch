# Safety、物理风险与控制约束

机器人服务可以高可用、通信可以加密、操作员也可以在环中，系统仍可能在错误时机发出会伤人的动作。Safety 关注系统行为如何导致不可接受的损失；Security 与可靠性会影响它，却都不能单独证明它。

本文位于[质量属性目录](/quality-attributes)，承接[质量属性总览](/quality-attributes/qa-00)和[可靠性与恢复](/quality-attributes/qa-02)，用仓库机器人说明从数字决策到物理过程的控制边界。

## 学习问题

- Safety、Security 与可靠性为何不能互相替代？
- 怎样从损失和危害推导控制结构与安全约束？
- 四类不安全控制动作分别如何进入测试？
- 何时进入 fail-safe、降级模式或人工接管？

## 定义与业务目标

**来源事实：** [FAA Order 8040.4C](https://www.faa.gov/documentLibrary/media/Order/FAA_Order_8040.4C.pdf)提供其航空组织语境中的安全风险管理要求；它不是跨行业合规标准。[STPA Handbook](https://psas.scripts.mit.edu/home/get_file.php?name=STPA_handbook.pdf)提供从损失、危害、控制结构和不安全控制动作分析约束的方法。本站只总结事实，不镜像、翻译或改编其图。

| 质量 | 核心问题 | 可能重叠 | 不能推出 |
| --- | --- | --- | --- |
| Safety | 系统行为会不会造成不可接受的物理或环境损失 | 故障、攻击、操作与环境 | “无故障”即安全 |
| Security | 威胁者能否破坏资产和控制 | 命令、身份、完整性 | “已加密”即安全 |
| 可靠性 | 系统能否持续给出规定服务 | 传感、通信、执行器失效 | “高可用”即安全 |

**本站分析：** 业务目标不是消灭所有风险，而是识别不可接受损失，控制导致损失的系统状态，并由有权限的安全责任人接受、限制或拒绝残余风险。风险矩阵可帮助排序，不能代替因果控制分析。

## 质量属性场景

以下六字段是本站原创仓库机器人场景。所有数值阈值都是等待领域工程、法规和试验导出的占位符，不是通用常数。

| 字段 | 场景 |
| --- | --- |
| Source | 路径规划器、操作员或通信中断 |
| Stimulus | 障碍物出现时仍请求机器人进入共享通道 |
| Environment | 传感质量下降、网络延迟、人员可能进入作业区 |
| Artifact | 状态估计、控制器、执行器、急停、反馈与操作界面 |
| Response | 阻止危险动作，进入受限速度或 fail-safe，并按条件人工接管 |
| Response measure | 危害状态未形成；反馈、权限、时序和执行器可用性均可核对 |

### Source

路径规划器、操作员或通信中断。

### Stimulus

障碍物出现时仍请求机器人进入共享通道。

### Environment

传感质量下降、网络延迟、人员可能进入作业区。

### Artifact

状态估计、控制器、执行器、急停、反馈与操作界面。

### Response

系统阻止危险动作，进入受限速度或 fail-safe，并按条件人工接管。

### Response measure

危害状态未形成；反馈、权限、时序和执行器可用性均可核对。

证据需要覆盖命令发出、执行器实际响应和物理过程反馈，不能只看控制软件返回成功。

## 架构策略

本站原创控制链把分析顺序固定为：损失 → 危害 → 控制结构 → 不安全控制动作 → 安全约束 → 残余风险接受与运行证据。

```mermaid
flowchart LR
  L[不可接受损失] --> H[系统级危害]
  H --> C[控制结构与反馈]
  C --> U[不安全控制动作 UCA]
  U --> S[安全约束与降级条件]
  S --> R[残余风险接受]
  R --> E[运行证据与重新评估]
  E --> C
```

四类 UCA 必须分别检查：需要控制时未提供；在不安全情境下提供；时机或顺序错误；持续过久或过早停止。它们不是故障代码分类，而是控制动作与过程状态之间的危险关系。

fail-safe、降级模式和人工接管必须写清进入与退出条件。接管方要获得足够反馈，拥有明确权限，在允许时序内作出动作，并确认通信和执行器可用性；如果这些条件不成立，“human in the loop”只是标签。急停还需独立于普通控制路径，并验证动作确实到达物理执行器。

## 测量信号与阈值

至少记录传感置信度、状态估计年龄、命令、确认、执行器位置、速度、制动状态、反馈延迟、控制权限、接管请求、响应时间、降级状态和安全约束违反。数值必须由具体设备、场地、人员暴露、制动性能和主管要求推导。

通过标准是声明的危险状态受到约束、停止或降级路径在实际执行器上生效，并且残余风险由指定责任人依据运行证据重新评估。仿真、单元测试或认证标签都不能单独覆盖这些证据。

## 权衡与失败模式

更保守的停止条件降低物理风险，却可能造成频繁停机和绕过诱因；更多冗余改善单点失效，却增加共因故障和状态分歧；人工接管提供额外判断，却受认知负荷、反馈延迟与权限冲突影响。安全约束要优先于吞吐目标，并明确降级状态允许的能力。

失败模式是把高可靠或冗余当作 Safety，因为两个一致但错误的状态估计会可靠地发出危险命令，导致物理损失。另一个反例是把“人工在环”当作保护，却没有可用反馈、操作权限、接管时限或执行器通道。STPA、风险矩阵、冗余、Security 控制和认证标签都不证明 Safety；对于没有物理、环境或不可逆高后果作用的纯信息工具，不适用完整物理安全分析，但仍需检查数据和业务伤害。

## 说明性场景

**说明性场景：** 机器人准备进入共享通道时，障碍物传感置信度下降且反馈超出领域阈值占位。控制器不得继续原速度命令，而要进入受限状态；若急停链、操作员反馈、接管权限或执行器可用性任一不足，则保持 fail-safe。只有物理反馈确认停止、危害解除且安全负责人接受残余风险后，才允许恢复。

**基于证据的推断：** 这说明控制动作必须结合环境和反馈判断。它不证明某一阈值适用于所有机器人，也不把方法完成、可靠性、人工复核或认证当作安全保证。
