# 生产事故响应智能体：把诊断建议与变更授权分成两条身份链

事故期间，最危险的自动化不是“诊断得慢”，而是把一个看似合理的解释直接变成生产写入。遥测可能陈旧，追踪关联可能缺失，人工也可能正在变更同一对象；此时更快执行只会更快放大不确定性。

这份说明性参考设计把响应拆成两条身份链。只读诊断链可以收集证据、维护版本化假设并提出候选动作；变更链只能接收事故指挥官明确批准的窄幅意图。恢复验证另行读取服务指标，不能由执行器自行宣布成功。

本文由 Tego Arch 架构知识项目整理。谷歌站点可靠性工程教材只支持事故分工与监控，美国国家标准与技术研究院的人工智能风险管理框架只支持风险治理。AWS 的身份与访问管理文档、Temporal 与 Kong AI Gateway 的官方材料分别支持最小权限、幂等活动和指标接口。

这些都是局部机制。本文不是真实客户部署，也不指向任何特定客户；没有任何来源证明本文的完整拓扑。事故与结果均为说明性，不代表生产经历、客户、指标或效果保证。

## 学习问题

- 告警进入后，严重度策略、只读诊断、假设评估与人工指挥分别控制什么？
- 为什么诊断身份和变更身份必须分离，且人工指挥保留最终授权？
- 版本化假设怎样同时保存支持证据、反证和数据新鲜度？
- 一个被批准的变更怎样缩窄为可识别、幂等并可查询结果的动作？
- 遥测、批准、写入或回滚不确定时，何时降级，何时明确弃权并转人工？

## 一页摘要

**已证实事实**：谷歌站点可靠性工程教材的事故管理章节把事故指挥、操作工作、沟通和计划分开，并指出事故中的生产修改应由指定操作角色承担。监控章节区分面向用户症状的黑盒观察与系统内部信号。美国国家标准与技术研究院的人工智能风险管理框架提供面向 AI 风险的治理、测量和管理方法；AWS 身份与访问管理文档要求只授予完成任务所需权限；Temporal 官方文档建议把可重试活动设计为幂等。

这些机制共同支持“分权、留痕、测量、最小权限与安全重试”，却没有定义一个事故响应智能体。参考设计因此增加一条强边界：诊断身份只能读，变更身份只能执行已经批准的窄意图，人工指挥拥有最终授权，任何数据不确定或权威冲突都优先停止自动化。

| 阶段问题 | 权威状态 | 控制所有者 | 禁止捷径 |
| --- | --- | --- | --- |
| 是否需要响应 | 告警来源、影响、严重度与变更预算 | `Policy Router`、值班政策 | 模型自行提高权限或忽略告警风暴 |
| 可能发生了什么 | 带时间戳的只读证据、版本化假设与反证 | `Read-only Diagnostic Agent`、`Hypothesis Ledger` | 把猜测写成根因事实 |
| 是否允许改变 | 候选动作、目标、前置条件、回滚与批准有效期 | `Incident Commander`、`Approval Gate` | 诊断凭据直接调用写工具 |
| 是否真正恢复 | 权威系统结果与服务指标的独立比较 | `Recovery Verifier`、`Manual Control` | 执行成功等同服务恢复 |

结论不是“让模型更谨慎”，而是让身份、状态和终止条件可执行。模型可以形成建议；只有人类指挥链能授权生产写入，服务权威和恢复指标决定动作结果。

## 事实边界

谷歌站点可靠性工程页面是公开教材内容，支持事故角色、统一指挥与监控术语；美国国家标准与技术研究院的人工智能风险管理框架是自愿、非行业特定的风险框架。AWS、Temporal 和 Kong AI Gateway 页面分别说明最小权限、活动幂等与指标接口。它们都不证明本设计已经部署，更不证明自动诊断准确或变更安全。

| 证据层 | 可以采用 | 不能推出 |
| --- | --- | --- |
| 谷歌站点可靠性工程教材与章节 | 明确角色、事故指挥、唯一写入工作组、监控与告警原则 | 本文智能体拓扑、任意组织都适用的严重度政策 |
| 美国国家标准与技术研究院人工智能风险管理框架 1.0 | 风险治理、测量、监控与人工监督的通用框架 | 某个假设评估器已合规或可自动批准变更 |

**基于证据的推断**：把“能解释证据”与“能修改生产”隔离，可把一个错误假设的后果限制在建议层。该推断成立的前提是身份系统真的分离凭据、批准对象可精确绑定目标和有效期，并能查询变更与服务的权威状态。

## 控制权与任务流

**说明性场景**：服务指标触发一组相关告警。场景不描述真实事故或客户，也不提供虚构时长、错误率、准确率或恢复结果；它只演练各阶段的控制合同。

| 阶段 | 输入与动作 | 产出状态 | 失败、超时或终止 |
| --- | --- | --- | --- |
| 告警接收 | 合并同源告警，应用严重度、影响与变更预算政策 | 事故身份、策略版本、只读范围 | 告警风暴时降级为去重与汇总，不扩张动作权限 |
| 只读取证 | 诊断身份查询日志、指标、追踪与最近变更 | 带来源、时间戳、新鲜度和缺口的证据 | 遥测陈旧或关联缺失时标记不确定，不补造链路 |
| 假设维护 | 写入版本化假设、支持证据、反证与待验证项 | 可比较的假设版本 | 看似合理但错误的假设必须能被反证降级 |
| 评估排序 | `Evaluator` 检查证据覆盖、矛盾和安全边界 | 排序结果或明确弃权 | 数据不确定、矛盾未解或预算耗尽时停止自动化 |
| 人工批准 | 指挥官审阅目标、预期、前置条件、回滚与期限 | 绑定目标和版本的批准意图 | 批准超时、并发人工变更或授权漂移时失效 |
| 窄幅变更 | 独立变更身份提交幂等键与前置条件 | 可查询的操作身份 | 结果未知时不得换键重试；交人工查询权威状态 |
| 恢复验证 | 独立验证器比较服务指标与事故前置基线 | 恢复、未恢复或不确定 | 未恢复则回滚；回滚失败或假恢复进入人工接管 |

诊断工具与变更工具使用不同身份、不同凭据和不同允许动作。诊断身份只能读取规定证据面；变更身份不能自由探索，只能消费批准门签发的目标、操作、前置版本、幂等键、截止时间和回滚意图。

人工指挥保留最终授权。`Incident Commander` 可以拒绝候选动作、缩小目标、撤销批准或直接把事故交给 `Manual Control`；智能体不能因严重度高、等待超时或置信分数高而替代该决定。

## 架构决策与权衡

**个人分析**：事故自动化首先应优化“错误时能安全停在哪里”，而不是自动动作数量。只读诊断可以更积极地并行收集证据；越接近不可逆写入，控制应越窄、越可寻址并越依赖人工授权。

| 决策 | 获得 | 付出 | 适用边界 |
| --- | --- | --- | --- |
| 读写身份硬分离 | 错误假设不能直接获得生产写权限 | 凭据、工具目录与审计链更复杂 | 生产变更后果高且身份系统可表达最小权限 |
| 假设版本保存反证 | 排序变化和弃权理由可复核 | 账本写入与证据新鲜度管理增加 | 诊断有多源证据且根因不确定 |
| 指挥官签发窄意图 | 人类最终授权可绑定目标、版本与期限 | 批准等待成为延迟与可用性风险 | 变更可以拆成小操作并有明确所有者 |
| 幂等键加前置条件 | 超时后可查询同一操作，减少重复效果 | 权威系统必须保存操作身份和冲突语义 | 外部 API 真正支持语义幂等与结果查询 |
| 独立恢复验证 | 避免执行器把命令成功误报为服务恢复 | 需要可靠基线、窗口和多信号解释 | 服务指标能反映用户症状且允许不确定结论 |

审批不是安全装饰。批准对象若只写“修复服务”，执行器仍拥有解释和扩大范围的空间；有效批准必须绑定事故、资源、预期版本、窄动作、幂等键、截止、变更预算和回滚条件。

恢复验证也不是一次布尔检查。验证器需要明确观察窗口、数据新鲜度、用户症状、内部信号和反向指标；若任何关键输入缺失，它应输出“不确定”并把控制交给人，而不是选择最接近成功的状态。

## 生产化分析

生产合同必须把失败映射为遏制、降级、恢复验证和终止动作。下表覆盖九个必需失败；其中超时和部分失败都是持久状态，不能被异常处理器抹平成一次普通重试。

| 失败模式 | 检测与遏制 | 降级、恢复或人工动作 | 停止自动化条件 |
| --- | --- | --- | --- |
| 遥测陈旧 | 比较采集时间、处理延迟和查询时间 | 只读补采或缩小结论，标记数据不确定 | 关键服务指标超过新鲜度政策 |
| 缺少追踪关联 | 请求、发布或资源身份无法连接证据 | 改用可验证指标与日志，保留关联缺口 | 候选动作依赖无法证明的因果链 |
| 告警风暴 | 同源告警速率和重复签名触发合并 | 只做去重、影响汇总与人工通知 | 路由器无法稳定识别事故范围 |
| 看似合理但错误的假设 | 反证或新证据推翻排名 | 版本化降级，撤销依赖它的候选动作 | 没有足够证据支持任何安全动作 |
| 批准超时 | 批准未在有效期内完成 | 保持只读诊断或明确弃权 | 不得把等待超时解释为默许 |
| 并发人工变更 | 目标版本或变更锁与批准前置条件冲突 | 使批准失效，重新读取权威状态 | 无法确认当前命令所有者或目标版本 |
| 变更结果未知 | 请求已发出但结果和权威状态不一致 | 用同一操作身份查询，不换键重放 | 查询仍不确定或重复可能产生第二次效果 |
| 回滚失败 | 回滚操作终态失败或服务仍未恢复 | 进入 `Manual Control`，冻结额外自动变更 | 回滚预算耗尽或安全边界受威胁 |
| 假恢复 | 单一指标改善但用户症状、反向指标或窗口不满足 | 延长观察、撤销恢复结论或人工核验 | 无法取得完整恢复证据 |

降级运行仅允许告警归并、只读查询、假设更新、人工简报和结果查询。它不能开放写权限、跳过反证、延长过期批准、提高变更预算或把部分失败写成恢复。

自动化在四类条件下停止：数据不确定，身份或命令权威冲突，候选动作触及安全边界，变更或回滚预算耗尽。系统应明确弃权并进入 `Manual Control`；人工可以继续调查或操作，但新的生产写入不再继承旧批准。

## 可迁移经验

迁移前先列出读权威、写权威、批准权威和恢复权威。若四者最终落到同一个模型会话或同一长期凭据，图再完整也没有形成控制边界。

### 可直接复用的机制

1. 告警入口固定事故身份、严重度政策、证据范围与变更预算。
2. 诊断身份只读，假设账本为每个版本保存支持证据、反证、时间戳和不确定项。
3. 评估器只能排序、挑战或弃权，不能签发生产批准。
4. 人工批准绑定窄动作、目标版本、幂等键、有效期、回滚与预算。
5. 恢复验证独立读取服务权威和用户症状，失败则回滚或转人工。

### 只能有限类比的部分

1. 谷歌站点可靠性工程的职责分离可支持统一指挥，不替组织定义值班、严重度或监管责任。
2. 美国国家标准与技术研究院的人工智能风险管理框架可支持风险治理与测量，不证明某个评估器准确，也不授予生产写权。
3. Temporal 的幂等活动建议可类比安全重试，前提是目标系统提供稳定操作身份和语义合同。
4. Kong AI Gateway 指标接口可类比可观测接缝，不能替业务选择恢复服务指标或判断数据新鲜度。

### 不应照搬的部分

1. 不要让诊断身份拥有生产写工具，也不要由执行器批准自己或验证自己。
2. 不要把高置信度、单一指标改善、命令成功或 HTTP 接受响应当作根因或恢复事实。
3. 不要在未知变更结果后换幂等键重试，也不要用新事故身份掩盖旧操作。
4. 不要把本文事故、图、节点或失败表述为客户部署、真实结果、生产基准或来源实现。

最终迁移条件可以直接审计：只读证据可追溯，假设可被反证，人工指挥拥有最终授权，批准意图不能越界，变更结果可查询，恢复需要独立服务指标。任一条件无法成立时，正确动作是停止自动化并交还人工控制。本参考设计收录在[案例目录](/cases)，并位于[智能体架构学习路径](/paths/agentic-architecture)的生产验证阶段。
