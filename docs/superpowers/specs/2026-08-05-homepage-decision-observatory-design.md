# Tego Arch 首页「架构决策观察」重设计

日期：2026-08-05  
状态：已完成对话设计，等待书面规格复核

## 1. 背景

现有首页已经能说明 Tego Arch 面向高级工程师、提供完整架构知识体系，并展示初版路线图、案例、学习路径、未来产物和贡献入口。但它仍然以“解释项目”为主，而不是先回答访问者为什么值得进入。

当前问题不是局部样式，而是文案、信息架构与视觉表达共同造成的：

- Hero 标题“从高级工程师到架构设计者”直接描述职业转换，更像受众标签，不像网站的核心主张；
- “初版先完成一套完整的架构知识体系”等标题使用口语化项目说明，不适合作为首页章节标题；
- 多数区块都采用大标题、说明段、硬边框或卡片，导致节奏重复、内容被切得过碎；
- 路线图使用完整长备注，桌面显得僵硬，手机端形成过重的连续阅读负担；
- 大字号宣言、深色光晕、圆角悬浮卡片会使页面接近消费电子发布页，弱化工程研究项目应有的克制感；
- 迁移地图、五步阅读协议、完整案例集合和扩展入口同时出现在首页，使首页承担了目录页和项目说明书的职责；
- 手机端只是把桌面内容堆叠，没有主动降低状态数字、案例数量和解释文字。

本次重设计把首页从“项目说明书”改为“架构判断入口”。首页首先建立 Tego Arch 的判断力主张，再用少量明确入口引导访问者进入学习路径、案例与证据体系。

## 2. 已确认的设计选择

对话中确认以下方向：

1. 首页的核心承诺是“架构判断力”，不是职业晋升、知识数量或研究工具本身；
2. 视觉方向采用“架构决策观察站”，但去掉苹果式发布页的夸张大字、渐变光晕和悬浮卡片；
3. 首页采用“精选入口”，不再保留完整目录式总览；
4. 文案使用克制的命题句：短、有判断，但不喊口号；
5. 首页标题不使用句号；
6. 科技感来自结构、关系、状态与信息秩序，而不是装饰性特效；
7. 路线图通过羽化与页面融合，详细说明按需出现；
8. 手机端主动删减信息，而不是机械堆叠桌面内容。

## 3. 目标

1. 让新访问者在第一屏理解 Tego Arch 训练的是复杂约束下的软件架构判断力；
2. 用更像研究界面、少一点产品发布页的视觉语言建立专业可信感；
3. 把首页压缩成一条清楚的叙事主线：判断主张、初版坐标、进入方式、精选研究、后续产物、开放研究；
4. 重写所有保留区块的标题、说明和入口名称，使文案适合首页而不是项目管理文档；
5. 柔化路线图边界，简化默认备注，同时保持快照、图例、发布门槛与实时事实源的可访问说明；
6. 降低手机端的说明长度、状态数量与案例密度；
7. 保持项目状态、案例与来源数据继续来自现有生成数据，不引入第二份手工事实源。

## 4. 非目标

- 不修改路线图图片中的历史内容或状态；
- 不改变 `docs/content-backlog.md` 作为实时精确进度唯一事实源的边界；
- 不删除案例、迁移地图、五步阅读协议、模式、设计题、资料库或学习路径页面；
- 不重构内容生成器、案例目录、source ledger 或长期 backlog；
- 不在本次变更中实现便携小抄、精华学习路线或 Tego 实践内容；
- 不把首页做成营销落地页，不增加价格、客户 Logo、社会证明或转化漏斗；
- 不引入新的前端框架、动画库或设计系统依赖；
- 不重新生成路线图位图。

## 5. 品牌与内容声音

### 5.1 品牌定位

Tego Arch 是面向有经验工程师的软件架构判断与研究入口。它不承诺职位转换，也不提供可直接复制的“最佳架构”。它通过边界、状态、控制、质量属性、真实系统与一手证据，帮助读者形成可以解释、验证和演化的架构决定。

### 5.2 文案原则

- 标题使用短命题，不使用句号；
- 标题表达一个判断或邀请，不解释项目管理动作；
- 正文只补充标题无法承载的必要上下文；
- 避免“赋能、颠覆、重新定义、最佳实践、终极、全栈、从零到一”等营销词；
- 避免把“高级工程师”“架构设计者”作为主标题；它们可以保留在 README 或适合人群说明中；
- 避免连续使用“进入、查看、浏览、开始”等同义入口；按钮应说明读者下一步获得什么；
- 英文只用于小型身份标签或研究编号，不作为每个区块的主要标题；
- 中文标题优先使用自然语序，不为形成口号而故意省略关键语义。

### 5.3 首页核心文案

Hero：

- 标签：`Tego Arch / 架构决策观察`
- 主标题：`在复杂系统里 做清醒的选择`
- 说明：`从边界、状态、控制与质量属性出发，让每个架构决定都能解释、验证和演化`
- 主入口：`开始建立判断坐标`
- 次入口：`了解研究方法`

页面元信息：

- 页面标题继续使用 `Tego Arch`，避免搜索结果标题被宣传语占满；
- description 调整为与 Hero 说明一致的完整句子，可在元信息中保留句号；“标题不使用句号”仅约束可见章节标题。

## 6. 首页信息架构

首页保留六个连续区段。

### 6.1 Hero：架构决策观察

Hero 建立项目的核心主张，不再描述职业转换。

内容：

- Tego Arch 身份标签；
- 主标题与一条简短说明；
- `/paths` 主入口；
- `/intro` 研究方法入口；
- 由 `projectStatus` 生成的紧凑状态栏。

状态栏只显示三个信息：

- 研究主题：`projectStatus.content_documents`；
- 治理来源：`projectStatus.governed_sources`；
- 当前研究：`projectStatus.durable_stories.current`。

不再展示独立的“PROJECT STATUS”卡片、持久故事完成比例与长状态说明。实时状态边界在路线图说明中集中表达。

### 6.2 初版路线：一张持续展开的架构坐标

- 编号标签：`01 / 初版路线`
- 标题：`一张持续展开的架构坐标`
- 说明：`初版沿一条可验证的研究路线展开。首页保留方向，实时进度回到 backlog`
- 展示现有路线图图片；
- 默认备注：`初版路线图 · 2026-08-05 快照`；
- 桌面提供“状态与图例说明”；
- 手机提供“查看大图”和默认收起的“关于这张路线图”。

### 6.3 进入方式：从问题出发

- 编号标签：`02 / 进入方式`
- 标题：`从问题出发`
- 说明：`选择与你当前任务最接近的入口，不必先读完整个知识体系`

三个入口采用研究目录行，不采用悬浮卡片：

1. `建立判断坐标` → `/paths`  
   说明：`理解驱动因素、边界与权衡如何连成主线`
2. `拆解真实系统` → `/cases`  
   说明：`观察控制、状态、协议与失败在系统中如何发生`
3. `回到证据现场` → `/references`  
   说明：`核对标准、源码、论文与一手工程材料`

模式和设计题仍保留在全局导航与各自页面，不在首页重复成为一级入口。

### 6.4 研究档案：正在研究的系统

- 编号标签：`03 / 研究档案`
- 标题：`正在研究的系统`
- 说明：`从真实案例观察架构选择如何落到控制、状态、协议与失败边界`

首页只展示三份精选案例。第一份作为较大的主档案，另外两份作为紧凑列表；提供一个进入完整案例库的文本链接。案例仍来自 `featuredCases`，不手工复制标题、摘要、来源类型或迁移目标。

首页不再展示完整五案例网格，也不展示迁移地图。迁移内容继续由案例库和模式页承载。

### 6.5 后续产物：下一步，让完整内容变得更轻

- 编号标签：`04 / 后续产物`
- 标题：`下一步，让完整内容变得更轻`

三个方向改为一条轻量列表，不使用三张独立卡片：

- `便携小抄`：守住第一性原理与高代价错误；
- `精华学习路线`：从完整体系提取连贯学习线索；
- `Tego 实践与规划`：说明判断在 Tego 设计中的应用与后续方向。

本区不增加按钮或空链接。

### 6.6 开放研究：这是一份开放的研究记录

- 标签：`OPEN RESEARCH`
- 标题：`这是一份开放的研究记录`
- 说明：`欢迎修订证据、补充案例、贡献原创图示，或改进研究工具链`
- 主入口：`参与修订与共建`，链接 GitHub README 的贡献章节；
- 次入口：`查看贡献方法`，链接 README 或站内研究方法，实施时只保留一个不重复的目标。

## 7. 从首页移出的内容

下列内容不删除，但不再出现在首页：

- 完整迁移地图；
- 五步阅读协议；
- 五张首发案例网格；
- “为上百个案例留下稳定入口”区块；
- 独立大尺寸项目状态卡；
- 每个后续产物的长段说明。

这些内容分别回到案例库、模式页、学习路径、资料库、README 和 backlog。首页不再承担这些页面的摘要合集职责。

## 8. 视觉系统

### 8.1 总体气质

采用“架构决策观察站”的工程研究气质：冷静、精确、可追溯。视觉不模仿消费电子发布页或 SaaS 营销页。

### 8.2 色彩

- Hero 使用稳定的炭灰色纯色背景；
- 正文继续使用现有暖白纸张色；
- 砖红继续作为操作、编号和焦点强调色；
- 蓝灰、黄褐只用于低密度关系图节点，不形成彩色渐变背景；
- 不使用发光渐变、霓虹描边或大面积高饱和色块；
- 深色模式继续使用现有中性暖黑变量，并确保 Hero 与正文仍有层级差。

### 8.3 字体与层级

- 继续复用现有中文衬线标题、无衬线正文和等宽编号字体；
- Hero 标题桌面目标范围约 `3rem–4.25rem`，不得恢复到接近 `5.8rem` 的发布会尺寸；
- 手机 Hero 标题控制在约 `2.25rem–3rem`，最多三行，不横向裁切；
- H2 桌面约 `2rem–2.75rem`，手机约 `1.65rem–2.1rem`；
- 标题字重中等，避免粗黑与高对比同时使用；
- 标题不使用句号。

### 8.4 边框、圆角与阴影

- 普通区块不使用完整外框；
- 分区依靠留白、编号与低对比结构线；
- 圆角控制在 `0–6px`，路线图说明浮层可使用小圆角；
- 普通入口和内容列表不使用悬浮阴影；
- 路线图图片不使用边框和投影；
- 说明浮层允许使用一层低强度阴影，以区分临时浮层与正文。

### 8.5 装饰与关系图

Hero 可使用一组低对比网格、三到五个关系节点与连接线作为背景结构。它只表达“关系与判断”，不承担真实拓扑或事实信息，因此：

- 必须标记为装饰，不进入读屏顺序；
- 不使用动画；
- 不覆盖正文对比度；
- 手机端降低透明度或隐藏部分节点；
- 不使用生成式人物、设备渲染或伪三维产品图。

### 8.6 动效

- 链接、目录行与说明浮层使用不超过 `160ms` 的状态反馈；
- 不使用视差、滚动触发大动画、数字滚动或连续背景动画；
- 遵守 `prefers-reduced-motion`；
- 路线图说明的出现与消失不得影响页面布局。

## 9. 路线图视觉与交互

### 9.1 图片融合

路线图取消边框与阴影。图片边缘通过容器伪元素或 CSS mask 使用页面同色渐变实现羽化；实现不得修改原 PNG 像素，也不得让文字区域变得不可读。

浅色与深色模式分别使用对应页面背景变量融合，避免在深色模式出现固定暖白矩形硬边。

### 9.2 桌面说明

默认只显示：

`初版路线图 · 2026-08-05 快照`

“状态与图例说明”在悬浮或键盘聚焦时显示非模态说明浮层。浮层内容包括：

- 这是历史快照，不是实时状态；
- 绿色表示快照当日已完成；
- 橙色表示快照当日当前阶段；
- 蓝色表示快照当日待执行；
- 每个阶段需经过验证、评审、发布与线上检查；
- 实时进度链接到 `docs/content-backlog.md`。

浮层必须支持键盘聚焦，不能只由鼠标 hover 触发。

### 9.3 手机说明

手机没有 hover 依赖：

- 默认显示 `2026-08-05 快照`；
- 提供 `查看大图`；
- 使用语义化 `details/summary` 展示“关于这张路线图”；
- 折叠内容复述颜色语义、发布门槛与 backlog 事实源；
- 默认保持收起，避免图片后紧跟长段备注。

### 9.4 加载与性能

- 保留 `loading="lazy"`；
- 保留 `decoding="async"`；
- 保留固有宽高，避免布局偏移；
- 生产 HTML 不得为完整路线图生成 preload；
- 不为实现羽化生成第二份大尺寸图片。

## 10. 响应式行为

### 10.1 桌面

- Hero 内容宽度受控，装饰关系图位于右侧背景；
- 状态栏显示三个值；
- 三个进入方式使用横向目录行；
- 研究档案使用一个主档案加两个紧凑档案；
- 后续产物使用一行三列轻量文本。

### 10.2 平板

- Hero 保持单列正文，关系图降级为背景；
- 进入方式仍可使用目录行；
- 研究档案转为两列或单列；
- 不出现固定最小宽度导致的横向滚动。

### 10.3 手机

- Hero 标题最多三行；
- 只保留两个状态数字，当前研究可移入辅助文本或省略；
- 说明正文缩短为一行核心承诺；
- 三个进入方式隐藏详细说明，只保留编号、标题与箭头；
- 研究档案最多突出两份内容，其余通过案例库入口访问；
- 后续产物垂直排列；
- 路线图说明默认收起；
- 页面不得产生横向溢出。

## 11. 可访问性

- 保持一个可见 H1 和递进的 H2/H3 结构；
- Hero 装饰图形标记为 `aria-hidden`；
- 目录行整行可点击时仍提供明确的可访问名称；
- 焦点样式继续复用全站焦点变量；
- 路线图保留目的型 alt；
- 路线图状态不只依赖颜色；
- 桌面浮层支持 hover 与 focus-within；
- 手机详细说明使用原生 `details/summary`；
- `查看大图` 必须有明确目标或打开可关闭的语义化大图视图，不能是无行为文案；
- 深色与浅色模式都满足正文和操作元素的可读对比；
- `prefers-reduced-motion` 下取消非必要过渡。

## 12. 数据与组件边界

### 12.1 数据

- 状态继续从 `src/generated/project-status.json` 读取；
- 精选案例继续从 `featuredCases` 派生；
- 不在 JSX 中手写状态数字、当前故事或案例事实；
- 路线图日期可作为历史快照元数据写在首页，因为它描述固定资产，不描述实时项目状态；
- backlog 继续是实时进度唯一事实源。

### 12.2 组件

首页实现可保留在 `src/pages/index.tsx`，但应拆成职责明确的局部组件或小型首页组件：

- Hero 与状态栏；
- SectionIntro；
- RoadmapDisclosure；
- EntryList；
- ResearchHighlights；
- FutureOutputList；
- ContributionBand。

组件不建立新的通用设计系统层。只有真实复用的首页结构才提取；简单标记保持局部实现。

## 13. 实现范围

不修改：

- 路线图 PNG；
- README 主体定位；
- 内容文档；
- backlog 状态；
- source ledger 与生成数据。

## 14. 测试与视觉验证

### 14.1 定向测试

测试应锁定：

- 新 Hero 标签、标题、说明和两个目标链接；
- 旧标题“从高级工程师到架构设计者”不再出现在首页；
- 旧路线图标题“初版先完成一套完整的架构知识体系”不再出现；
- 六段首页结构按顺序出现；
