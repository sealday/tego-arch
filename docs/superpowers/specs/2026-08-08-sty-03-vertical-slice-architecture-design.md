## 1. 目标与非目标

本主题新增一篇可独立阅读的架构风格文章，解释垂直切片架构如何以业务能力或用例作为主要组织单元，减少一次变化穿越多个共享技术层的范围，并明确其与分层架构、六边形/洋葱/整洁架构以及模块化单体的边界。

文章必须强调：垂直切片不是固定目录模板；一个切片不是自动的独立部署单元、服务或数据库；真正的边界由业务不变量、数据所有权、依赖约束、变化压力和团队责任共同决定。

本轮不实现 STY-04，不新增运行时功能，不修改既有路由，不进行无关重构，也不把某一语言、框架、数据库或官方示例写成架构风格的强制要求。

## 2. 页面结构与核心内容

新增 `content/styles/sty-03-vertical-slice-architecture.mdx`，类型为 `style`，主题 ID 为 `STY-03`，正式页面 slug 为 `/styles/sty-03`。文章沿用现有风格页的十一段契约：

1. 学习问题
2. 组件、连接器与约束
3. 边界与控制流
4. 数据所有权与一致性
5. 部署单元与故障域
6. 团队拓扑
7. 质量属性收益与成本
8. 迁移路径
9. 禁用条件
10. 对比案例
11. 来源

统一场景是提交订单。文章同时呈现传统分层组织和垂直切片组织：

- 分层侧以控制器、应用服务、共享验证器/仓储和数据库为主要技术层；多个用例横向穿过共享层。
- 垂直切片侧以 `SubmitOrder` 用例边界为主要变化单元，集中输入、处理、必要的数据访问和响应映射；共享能力只有在不变量和变化压力确实要求时才抽出。
- 领域规则仍受保护，传输模型、数据库记录和外部响应不能直接充当领域模型。
- 切片先可以共存于同一个单体进程中；代码组织边界不自动推导部署、扩缩或故障域。

对比必须覆盖组织单元、控制流、依赖、数据所有权、一致性、部署、团队拓扑、质量属性收益与成本、迁移条件和禁用条件。STY-02 只用于说明依赖方向、边界转换与技术机制隔离的互补关系，不重复其三种架构的主体定义。

## 4. 来源与版权治理

至少新增并登记两类直接来源：

1. Jimmy Bogard 关于 Vertical Slice Architecture 的原始文章或可检查示例，用于核对按功能组织代码、减少跨功能共享层和请求处理边界的工程意图。

## 6. 错误处理与验证策略

内容和构建层面的失败必须显式暴露：

- 未登记外链、来源角色越界、许可证字段缺失时验证失败；
- 术语首次出现不满足中文优先规则时验证失败；
- STY-01/STY-02/STY-03 关系不互惠，或 STY-04 被提前激活时验证失败；
- 正文、图示节点和控制流不一致时定向测试失败；
- Draw.io/SVG 不成对、资产缺失、图示结构低于最小库存时定向测试失败；
- 宽表或图示在窄屏撑破文档时部署/浏览器验证失败；
- 任何 console warning、error 或 page error 均不得静默忽略。
