# Tego Arch 首页用户视角路线图设计

## 1. 背景

首页当前两张路线图延续了项目规划阶段的表达方式。第一张图包含故事编号、完成状态、当前阶段和发布日期；第二张图强调“并行演进”“不代表固定顺序或发布日期”。这些信息适合 README、backlog 和历史记录，却不是首页读者首先需要理解的价值。

两张图还使用高饱和蓝、绿、橙和暖白画布。浅色主题中它们像独立的白板稿，暗色主题中则形成明显的发光白色矩形，与站点的砖红、墨色和纸张色系统割裂。

本次设计把首页路线图从“项目状态说明”改为“用户理解辅助”。README 继续保留现有完整图片和历史边界；首页使用两张信息更少、主题一致的新编辑图。

## 2. 目标

1. 让首页标题和说明回答读者“这对我有什么用”，而不是解释项目如何推进。
2. 用第一张图说明架构判断如何形成，用第二张图说明知识体系可以怎样使用。
3. 降低手机端图内文字密度；详细说明继续由 HTML 文本承担。
4. 让两张图在浅色、暗色主题中都使用站点语义色，不再依赖白色羽化方块融入页面。
5. 保留 README 中完整路线图、历史快照、交付边界和三项未来方向说明。

## 3. 非目标

- 不修改 `docs/content-backlog.md`、项目状态或持久故事投影。
- 不重新解释或改写 README 中的历史快照。
- 不把三个使用方式实现为新的产品入口。
- 不修改三个方向的批准名称和英文行业术语。
- 不新增运行时依赖。
- 不把详细状态、日期、故事编号或交付承诺重新放进首页图片。

## 4. 首页文案

### 4.1 判断路径板块

- 标签：`01 / 判断路径`
- 标题：`建立架构判断的主线`
- 说明：`从基础与质量出发，经过建模、模式与治理，在案例和复盘中形成判断`

这组文案把第一张图从“初版路线”转为读者的学习与判断路径。首页不再展示历史状态说明、状态图例、快照日期和“查看项目进度”入口；这些内容继续由 README 与 backlog 承担。

### 4.2 使用方式板块

- 标签：`04 / 使用方式`
- 标题：`从理解架构到做出取舍`
- 说明：`需要判断时快速查，系统学习时沿路径走，也从真实架构中理解取舍`

图下三张 HTML 卡片继续保留：

| 中文名称 | 英文副标 | 首页短说明 |
| --- | --- | --- |
| 架构决策速查 | Architecture Decision Quick Reference | 用于设计、评审与复盘的决策参考 |
| 精选学习路径 | Curated Learning Paths | 按角色与任务场景组织学习序列 |

当前产品表面不得继续出现：

- `让完整体系进入不同使用场景`
- `三个方向并行演进，不代表固定顺序或发布日期`

历史 spec、plan 和已发布原图是设计记录，不进行追溯改写。

## 5. 首页专用编辑图

### 5.1 格式决策

选择 `位图`。

两张图承担概念性视觉总结：第一张表达一条逐步形成判断的路径，第二张表达一套知识体系的三种使用方式。它们不承担实时状态、精确项目拓扑或可执行流程，视觉记忆与页面融合比图源可编辑性更重要。

按 `illustrating-architecture-articles` 路由，使用 `imagegen` 生成亮色母版，再基于母版编辑暗色版本。暗色版本必须保持相同文字、几何关系和图标，仅替换主题色与背景。

### 5.4 视觉语言

两张图使用相同的项目专属编辑语言：

- 原创、克制的中文手绘编辑图，不模拟具体艺术家；
- 比现有白板稿减少边框、装饰线和图标数量；
- 保持充分留白，视觉重点是关系与短标签；
- 不使用人物、品牌标志、签名、水印、3D、照片质感或装饰性电路；
- 不以颜色单独表达顺序或含义。

亮色版本使用：

- 页面纸张：`#f7f2e8`
- 抬升纸张：`#fffaf0`
- 主墨色：`#292723`
- 柔和墨色：`#5d584f`
- 砖红强调：`#9f3f31`
- 分隔与辅助线：`#d8cebf`

暗色版本使用：

- 页面纸张：`#1f1d1a`
- 抬升纸张：`#292621`
- 主墨色：`#eee7dc`
- 柔和墨色：`#c5bbac`
- 浅砖红强调：`#e3907d`
- 分隔与辅助线：`#62594e`

禁止继续使用现有图片中的高饱和蓝、绿色完成语义和橙色当前语义。

### 5.5 画布与可读性

- 两张图使用相同的近 16:9 横向画布；优先保留 imagegen 原生 `1672×941` 输出。
- 不为迎合固定尺寸裁掉标签、节点或路径。
- 每张图在约 `720 px` 内容宽度与 `358 px` 手机宽度下，核心关系和全部标签都必须可读。
- 暗色版本不得由简单反相滤镜生成；必须目视核对背景、文字、强调色和辅助线的对比度。

## 6. 页面集成

### 6.1 README 边界

README 继续引用：

- `tego-arch-initial-release-roadmap.png`
- `tego-arch-future-directions.png`

README 的“初版方向”“未来三个方向”、历史快照说明、并行边界和完整三方向说明保持不变。首页专用编辑图不进入 README。

### 6.2 首页主题切换

首页使用 Docusaurus 现有 `ThemedComponent` 在浅色和暗色资产之间切换。它在服务端保留两种主题变体以避免 hydration 闪烁，在浏览器完成 hydration 后只呈现当前主题；两张变体都继续使用 lazy loading，避免自建颜色状态或主题切换逻辑。

组件继续提供：

- 明确的 `width` 与 `height`；
- `loading="lazy"`；
- `decoding="async"`；
- 目的型 `alt`；
- 主题切换后的正确资源呈现。

不新增依赖，不引入第二套颜色状态，也不自行读取 `localStorage`。颜色模式只来自 Docusaurus 的主题上下文。

### 6.3 版面处理

- 两张新图不使用厚边框、明显阴影、白色光晕或大圆角。
- 图片容器背景直接使用当前主题的 `--atlas-paper` 或 `--atlas-paper-muted`。
- 羽化仅用于处理纹理边缘，不能形成发光矩形。
- 第一张图移除状态悬浮说明、移动端详情和历史快照图注，因为首页专用图不再表达历史状态。
- 图下的 HTML 文本保持所有关键信息可访问，不依赖图片或 hover。

## 7. 数据、权利与来源边界

- 首页编辑图不读取 backlog，不随项目状态变化。
- 两张图是项目原创插图，由 `LICENSE-CONTENT.md` 与 `NOTICE.md` 的现有边界覆盖。
- 当前来源台账的 document key 只允许 `content/*.mdx`；首页 React 页面不能闭合台账引用。
- 不为首页专用图添加孤立 source，也不伪造内容页引用。只有未来真实 `content/*.mdx` 页面引用其中一张图时，才按当时 schema 登记。
- `data/source-ledger.json`、`src/generated/source-ledger.json` 和包清单保持不变。

## 8. 测试与验收

### 8.1 文案合同

- 首页包含两组批准的标签、标题和说明。
- 首页不再包含旧的未来方向项目管理文案。
- 三张 HTML 卡片的中英文名称与短说明保持不变。
- README 的完整历史文案和两张原图引用保持不变。

### 8.2 图片合同

- 四张首页专用 PNG 存在、可读取、尺寸一致且大于仓库最低位图阈值。
- 两个亮暗资产对分别保持相同宽高。
- 第一对只出现六个批准标签；第二对只出现四个批准标签。
- 首页只引用首页专用资产，README 只引用原始完整资产。
- 主题图片合同限定在对应组件内，不能被另一张图片的属性误满足。

### 8.3 视觉验收

在以下视口检查浅色和暗色主题：

- `1440×1000`
- `390×844`

每个视口必须满足：

- 两张图都使用当前主题版本；
- 无白色发光矩形、硬边、横向溢出或裁切；
- 图内所有标签可读；
- 图片不与标题、正文或三张卡片争抢层级；
- 英文副标不发生不可读碎裂；
- 主题切换后图片资源正确更新；
- 新组件与图片不产生 console error；
- 内容不依赖 hover。

### 8.4 工程验证

先运行受影响的 README、首页和图片合同测试，再运行：

```text
npm run typecheck
npm run build
npm run verify
git diff --check
```

最终独立评审必须明确 `Ready to merge: yes`。

## 9. 失败处理

- imagegen 出现错字、额外标签或错误关系时，不集成该版本。
- 暗色编辑导致文字、节点或关系变化时，重新从批准的亮色母版编辑，不接受近似复刻。
- 若四张图无法在手机宽度保持可读，继续减少装饰和图标，不增加图内说明文字。
- 若主题图片切换导致 hydration、闪烁或重复下载问题，先用聚焦回归证明，再选择最小的 Docusaurus 原生修复；不引入新的主题状态库。
- 若图片压缩影响标签清晰度，保留可读版本并在交付报告记录体积，不以模糊换取体积。

## 10. 完成标准

- 首页文案从项目推进说明转为用户的判断路径与使用方式。
- 首页使用四张新的亮暗主题编辑图；原始详细图继续留在 README。
- 两张首页图在桌面、手机、浅色和暗色主题中与页面色彩系统一致。
- 首页不再显示历史状态图例、快照日期或交付顺序说明。
- README、backlog、来源台账、依赖和生成来源保持边界不变。
- 聚焦测试、完整验证、四视口视觉 QA 和独立评审全部通过。
