# Draw.io 架构图 Skill 与 MOD-02 视觉修订设计

## 背景

MOD-02 已从 Mermaid 迁移为 `.drawio` 源文件与 SVG 发布文件配对的方案。首轮预览证明整体视觉质量更好，但也暴露了两类可读性缺陷：

- 连线标签以不透明底色覆盖连接线，标签像贴在线上，箭头语义被切断；
- 部分节点的标题、类型标签与边界间距过小，产生文字越界或即将越界的观感。

这些缺陷不应只在 MOD-02 中一次性修复。项目需要一个可复用的 Draw.io 架构图 skill，把布局判断、文件配对、机械校验和视觉验收固化下来。

## 目标

1. 在项目内创建可自动发现的 `$creating-drawio-architecture-diagrams` skill。
2. 同时保留可编辑的 `.drawio` 源文件和可直接发布的 SVG。
3. 防止连线标签遮挡线条、节点文字越界、标签与节点或箭头碰撞。
4. 将可机械判断的约束交给脚本，将需要视觉判断的部分保留为明确的 QA 流程。
5. 用新 skill 重画 MOD-02，并在本地桌面和移动视口中验证。

## 非目标

- 不实现通用 Draw.io XML 生成器或完整排版引擎。
- 不要求所有架构图使用相同拓扑或固定模板。
- 不在本次变更中批量迁移其他 Mermaid 图。
- 不把 SVG 当作唯一源文件，也不要求浏览器直接渲染 `.drawio`。

## 方案选择

### 方案 A：Skill + 布局规范 + 静态检查脚本

这是采用的方案。skill 保存工作流和判断规则；参考文件保存项目视觉语言、布局和导出约束；小型脚本检查配对文件、XML/SVG 基本结构和可机械识别的反模式。

优点是规则可复用、错误能尽早暴露，同时保留不同图表的布局自由。成本是仍需一次真实页面视觉验收。

### 方案 B：仅提供 Skill 文档

实现简单，但无法阻止源文件与发布文件失配，也不能稳定发现固定尺寸、HTML 标签等机械问题。

### 方案 C：完整 XML 生成器

一致性最强，但会过早固化图表类型、节点尺寸和路由策略。当前只有一个试点，不足以证明这种复杂度值得承担。

`SKILL.md` 只保留触发条件、核心原则、执行顺序、验收门槛和常见失败。详细尺寸、间距和文件集成规则按需读取。脚本只检查确定性约束，不声称替代视觉 QA。

## 布局与文字契约

### 节点文字

- 节点标题最多两行，优先一行；类型或角色标签单独占一条基线。
- 标题与节点左右边界至少保留 16 px 内边距，上下至少保留 14 px。
- 标题与类型标签基线之间至少保留 22 px；任何文字基线距节点底部至少 14 px。
- 先根据文字长度和行数确定节点宽高，再放置节点；不得先锁死小框再缩小字体补救。
- 正文节点字号不低于 15 px，类型标签不低于 10 px。长说明移入正文、图注或旁注，不塞入业务节点。

### 连线与标签

- 连线标签不能通过与背景同色的实色块擦除或覆盖连接线。
- 标签放在线段上方、下方或专门预留的空白通道中，与线条保持至少 8 px 视觉净空。
- 标签边界与箭头尖端保持至少 16 px 距离，与节点边界保持至少 12 px 距离。
- 两节点间的短连接线优先不加标签；若语义已由文章或节点表达，删掉标签。
- 关系文字保持短动词或动宾短语。长说明放入旁注或正文。
- 优先使用正交连线和明确的入口/出口点；为标签预留路由通道后再画线，避免线穿过标签、节点或其他标题。

### 信息层级

- 同一图只表达一种主要阅读方向。
- 容器、节点、外部依赖和关系必须有稳定的视觉语义。
- 颜色用于表达类别或边界，不作为唯一编码；文字、边框或形状仍要能区分角色。
- 图中不引入文章未证明的调用顺序、部署位置或故障语义。

## 文件与发布契约

- 可编辑源文件放在 `diagrams/<slug>.drawio`。
- 发布文件放在 `static/img/diagrams/<slug>.svg`。
- 两个文件共享 slug，文章只嵌入 SVG。
- Draw.io 标签默认使用纯文本，不在 `mxCell.value` 中嵌入 HTML。
- SVG 根元素必须使用 `viewBox`，不得固定根 `width` 或 `height`。
- SVG 必须包含 `<title>`、`<desc>`、`role="img"` 和可关联的 ARIA 标签。
- 每次修改图意、节点、关系或文字时，必须同步更新源文件与 SVG。

## 静态验证

`validate_drawio_svg.mjs` 接收 `.drawio` 和 SVG 路径，失败时返回非零状态。它检查：

- 两个文件存在且 slug 相同；
- Draw.io 和 SVG 都是可解析的 XML；
- Draw.io 包含 `mxfile` 和命名 diagram page；
- Draw.io 的 `mxCell.value` 不包含 HTML 标签；
- SVG 有 `viewBox`，根节点没有固定宽高；
- SVG 有可访问标题、描述和图像角色；
- 关键文本在源文件和 SVG 中均存在，可由调用方通过重复参数声明。

脚本不尝试计算字体真实渲染宽度，也不自动判断所有几何碰撞。这些属于浏览器视觉验收。

## Skill 的测试驱动验证

在创建 skill 前，先用当前 MOD-02 原始文件作为无 skill 基线，记录它对以下检查的失败：

- 连线标签以背景块覆盖线段；
- 下方两个节点的标题与类型标签基线间距不足；
- 现有测试只验证文件存在和响应式外壳，没有覆盖上述视觉契约。

然后添加针对静态脚本和项目契约的失败测试，再实现最小脚本与 skill 内容使测试通过。最后应用 skill 重画 MOD-02，确保同一组契约和页面视觉 QA 都通过。

## MOD-02 修订

保留“Context 在上、Container 在下”的双层结构和暖色视觉语言，调整如下：

- 上层关系标签移到连线上方，不再用色块切断线条；
- “展开目标系统”使用侧置标签或独立空白通道，虚线保持连续；
- 下层增加垂直空间，将数据库和任务执行器排成明确的两条路由；
- “创建支付任务”不再压在折线转角上；
- 支付任务执行器和外部银行增加节点高度，重新设置标题与类型标签基线；
- 关系标签与箭头、节点、边界保持契约规定的净空。

SVG 的 `viewBox` 可以随新布局增加高度，但文章仍以 50rem 图宽呈现，移动端继续使用局部横向滚动，不压缩到不可读。

## 验收

### 自动检查

- skill 目录通过 `quick_validate.py`；
- skill 的静态验证脚本有失败与成功用例；
- MOD-02 的 `.drawio` 与 SVG 配对测试通过；
- 全量测试、内容校验、类型检查和生产构建通过。

### 视觉检查

在本地生产预览中检查：

- 800 px 图宽下没有文字越界、标签遮线、箭头被标签切断或元素碰撞；
- 390 px 视口下页面本身不横向溢出，图在局部容器内平滑横向滚动；
- 滚动到图的左、中、右区域时，标签和节点仍完整；
- 浏览器控制台没有与该页面相关的错误。

## 完成条件

项目内 skill、参考文件、校验脚本、测试、更新后的 Draw.io/SVG 和文章集成全部提交；本地预览保持可访问，并提供更新页面与关键文件路径供用户查看。
