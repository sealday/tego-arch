# Tego Arch 未来三个方向路线图设计

## 1. 背景

Tego Arch 当前同时展示一张“初版发布路线图”历史快照，以及 README、首页中的三个后续产物。历史路线图承担初版研究进程说明，不能被未来方向替换；现有“初版之后”“后续产物”“便携小抄”“精华学习路线”等表达则过于接近内部讨论或口语，不适合作为长期产品语言。

本次变更保留初版路线图，新建一张“未来三个方向”路线图，并统一 README 与首页的命名、解释和视觉表达。未来方向不承诺固定顺序、完成状态或发布日期。

## 2. 目标

1. 把三个后续想法改写为业界常用、可长期使用的产物名称。
2. 明确完整架构知识体系是三个方向的共同基础。
3. 用一张与项目既有插图语言一致的新图表达三个并行方向。
4. 让 README、首页、图片、替代文本和测试使用同一套词汇。
5. 保留现有初版路线图的历史快照身份与状态边界。

## 3. 非目标

- 不修改或重新生成现有 `tego-arch-initial-release-roadmap.png`。
- 不把三个方向实现为可访问的新产品入口。
- 不承诺交付顺序、发布日期、完成比例或当前状态。
- 不新增运行时依赖。
- 不修改知识正文、backlog 状态或项目状态生成逻辑。

## 4. 统一命名

采用中文主标题与英文行业术语副标：

| 中文名称 | 英文副标 | 产物边界 |
| --- | --- | --- |
| 架构决策速查 | Architecture Decision Quick Reference | 面向方案设计、架构评审与故障复盘的快速工作资料 |
| 精选学习路径 | Curated Learning Paths | 按经验、角色与任务场景组织的短学习序列 |
| Tego 参考架构 | Tego Reference Architecture | 公开 Tego 的决策、权衡、验证结果与演进路线 |

这些名称分别对应业界常见的 Quick Reference、Curated Learning Paths 与 Reference Architecture 产物类型。中文名称承担主要阅读任务，英文副标用于建立行业语境，不作为装饰性英文。

## 5. README 文案

将 `## 初版之后` 改为 `## 未来三个方向`，并在标题后放置新路线图。

引导文案：

> 完整知识体系是共同基础。接下来将沿三个方向并行演进；它们代表不同的使用场景，不构成固定的交付顺序或发布日期。

三个方向使用以下完整说明：

### 5.1 架构决策速查

英文副标：`Architecture Decision Quick Reference`

> 把核心原则、决策检查项和常见失误模式整理成可快速查用的工作资料，服务方案设计、架构评审与故障复盘。

### 5.2 精选学习路径

英文副标：`Curated Learning Paths`

> 按经验阶段、角色与任务场景组织更短的学习序列，同时保留回到完整论证、真实案例和来源证据的入口。

### 5.3 Tego 参考架构

英文副标：`Tego Reference Architecture`

> 持续公开 Tego 的架构决策、取舍依据、验证结果与演进路线，形成可审视、可讨论，但不鼓励直接复制的实践参考。

## 7. 图片设计

### 7.1 格式决策

选择 `位图`。

这张图是概念性视觉总结，表达“一个共同基础、三个并行使用方向”，不承担精确拓扑、状态机或可执行流程。其价值来自统一方向感，而非确定性连接细节。

### 7.2 读者判断

完整架构知识体系将沿三种使用方式并行演进，三个方向之间不存在固定交付顺序。

### 7.3 视觉任务与结构

- 视觉任务：visual summary。
- 结构：左侧或中央的“完整架构知识体系”作为共同基础，分别连接三个并列方向。
- 连接：共同基础到三个方向各有一条独立连接；三个方向之间没有连接箭头。
- 关键边界：不得表达顺序、日期、完成状态、当前状态或交付承诺。

### 7.4 封闭标签

图片只允许出现以下文字：

1. `Tego Arch 未来三个方向`
2. `一套知识基础 · 三种使用方式`
3. `完整架构知识体系`
4. `架构决策速查`
5. `QUICK REFERENCE`
6. `精选学习路径`
7. `CURATED LEARNING PATHS`
8. `Tego 参考架构`
9. `REFERENCE ARCHITECTURE`
10. `并行演进 · 不代表交付顺序`

不得生成额外标签、段落、状态词、Logo、签名、水印或日期。

### 7.5 视觉语言

按照项目 `illustrating-architecture-articles` 技能：

- 16:9 横向暖白纸张；
- 原创中文手绘技术白板风格；
- 深蓝表示共同基础和连接结构；
- 橙色只承担方向强调，不表示进行中；
- 不使用绿色完成标记或红色失败标记；
- 使用简洁、项目中性的技术图标；
- 具有充足留白，文字在约 720 px 内容宽度仍可读；
- 不使用人物、品牌标志、装饰性电路、照片质感或 3D 效果。

### 7.6 资产与替代文本

- 发布路径：`static/img/illustrations/tego-arch-future-directions.png`
- README alt：`Tego Arch 从完整架构知识体系并行发展出架构决策速查、精选学习路径和 Tego 参考架构三个未来方向`
- 首页 alt 使用同一目的型描述。
- 首页图片设置固定宽高、`loading="lazy"` 与 `decoding="async"`。
- 图片生成后登记为项目原创插图，使用当前来源台账约定，不复用其他图片的 source ID。

## 8. 页面集成

### 8.1 README

现有初版路线图继续位于“初版方向”。新图只出现在“未来三个方向”，置于引导文案与三个方向详情之间。

### 8.2 首页

现有初版路线图板块不变。未来方向板块按以下顺序呈现：

1. 板块标签、标题和并行边界说明；
2. 新路线图；
3. 三个方向的中英文名称与短说明。

图片使用现有路线图的页面融合原则，不增加厚重边框或强投影。手机端保持完整宽度，不依赖 hover，不出现横向滚动。

## 9. 数据与依赖边界

- 三个方向是静态产品文案，不进入 `projectStatus`。
- 新图不读取 backlog，也不从当前研究状态推导内容。
- README 与首页共享同一概念词汇，但不新增运行时共享数据模块；当前体量下直接由测试锁定一致性更简单。
- 来源台账只登记原创插图的权利和使用边界，不将图片作为事实证据。

## 10. 失败处理

- 图片文字不准确、出现额外标签或在 720 px 宽度不可读时，不集成该版本。
- 若图像生成无法稳定呈现十个封闭标签，优先减少装饰元素；不得改变已批准词汇。
- 若手机端图片导致溢出，修复容器和响应式样式，不裁掉方向或文字。
- 若来源台账登记导致派生内容变化，提交仓库策略要求的生成结果并重新验证。

## 11. 测试与验收

### 11.1 文案合同

- README 与首页包含 `未来三个方向` 语义。
- 两处包含三个中文名称和对应英文副标。
- 两处不再包含本设计列出的旧产物称谓。
- 首页说明明确三个方向不代表固定顺序或发布日期。

### 11.2 图片合同

- 新 PNG 存在、尺寸合理且大于仓库最低位图阈值。
- README 与首页引用同一稳定资产。
- 首页包含目的型 alt、固定宽高、lazy loading 与 async decoding。
- 来源台账完整登记原创插图及 README、首页的使用边界。

### 11.3 视觉验收

- 原始尺寸与约 720 px 内容宽度下逐字核对十个封闭标签。
- 桌面与手机均无裁切、横向溢出和不可读标签。
- 浅色、深色主题中的图片边界与页面自然融合。
- 不依赖颜色区分三个方向或并行关系。

### 11.4 工程验证

先运行受影响的 README、首页与插图合同测试，再运行内容验证、生成内容检查、审阅健康、类型检查和生产构建，最终运行 `npm run verify`。
